# B2 — BRCB delivery, segmentation and client side (task of igs-iec61850-mms)

## Prompt

Run task B2 of `IMPLEMENTATION.md` (depends on B1, D4, D5): segmentation where a report exceeds the PDU size, the history kept, the client API for
the buffered blocks. Done when AT-10 passes between our client and server, and with the peer.

## Summary

- **Core** (`report/brcb.rs`, `report/encode.rs`): the buffered block now carries its own configuration (`brcb::Config`, with `BufferedFields`: the
  nine options of the buffered block), and emits `Action::Entered` for each entry, with its members. The layout of a buffered report
  (`buffered_information_report`) follows 8-1 table 74, with the inclusion bit string. D-038.
- **SCL** (`scl/build.rs`): a buffered `ReportControl` is built into `Configuration::buffered` (`bufOvfl`, `entryID`); SCOPE-002 changes accordingly.
- **Server** (`buffered.rs`, `reports.rs`, `model.rs`, `updates.rs`): a `BufferedBlock` per block, served as `node$BR$block$attribute`; the values of an
  entry are kept with it (the update's notice now carries the written value); the owner is the association that enabled the block; reports go to
  the owner only; a report over the segment budget is sent as segments.
- **Client** (`client_buffered.rs`, `igs61850-client buffered`): `buffered_values`, `buffered_write` (`BufferedWrite`), `decode_buffered_report`;
  the command line subcommand configures, enables and prints the reports, with an optional resumption from an entry.
- **Bug found by the peer, fixed**: the first decoder followed 7-2 table 73's order and rejected the reference server's reports; 8-1 table 74 is the
  wire order (D-038). The bit numbering of the options matched the peer's report without change.
