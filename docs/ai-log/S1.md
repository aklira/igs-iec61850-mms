# S1 — Parser and bounds (task of igs-iec61850-mms)

## Prompt

Run task S1 of `IMPLEMENTATION.md` (dependencies F1 and P5), in parallel with the preparation of P2 (7-1 and 61850-6 texts), which S1
does not need. ICD and CID parsing behind the feature `scl`, with external entities disabled, no network access, and bounds on size,
depth and instance count (SCL-004). Done when malicious XML cases are refused and a fuzz target is added.

## Summary

- Core, `scl` (feature `scl`, off by default): `parse(bytes, &Limits)` reads an SCL document into a tree of elements (name, namespace,
  attributes, children). It refuses a document type declaration before reading, runs roxmltree without DTD and with the default entity
  resolver (nothing is resolved), and checks the bounds while it builds the tree. D-018, D-019.
- Bounds: document size, nesting (capped at 256 whatever the limit asks), elements, instances, attributes per element, value length.
- Fuzz target `fuzz/fuzz_targets/scl_parse.rs` (cargo-fuzz, nightly, outside the workspace). A 90-second run ran about two million
  inputs without a crash.
- P2 (texts of 7-1 and 61850-6) was running in the background during this task; S1 does not use it.

## Tests

- 15 tests (`tests/scl_parse.rs`): a valid document read with its structure (namespace, attributes, instances, depth); external file,
  network and expansion-bomb entities refused; too large, too deep (and the depth cap), too many elements, instances, attributes, long
  values; a root that is not SCL; invalid XML and non-UTF-8; two property tests (arbitrary and mutated bytes never panic).
- Gate: fmt, clippy with `-D warnings` on all targets and all features, the workspace tests with all features (125 passed), `cargo deny`.

## Not done here

- The namespace and the XSD of the root, the semantic checks and the templates (S2); the atomic activation of a model (S3).
