# X4 — SGCB remainder: the names of the setting group control block (task of igs-iec61850-mms)

## Prompt

Run task X4 of `IMPLEMENTATION.md` (production phase X): the remainder of the SGCB, `Owner` and `GetNameList` (O3), with bench rows
against the reference peer.

## Summary

- The plan's premise needed a correction before any work: the Owner is not an attribute of the SGCB (7-2 table of §17.2 and the
  table 71 of 8-1 have none). It is an attribute of the BRCB and the URCB, and our BRCB serves it as an empty octet string (D-044).
- GetNameList: the SGCB and its six attributes are named variables of each device's domain (`src/setting_groups.rs`, `list`, called from
  `ServedModel::from_configuration`). The structure is typed as table 71 (INT8U, BOOLEAN, Timestamp, INT16U). Their reads and writes are
  still answered by the setting group handler before the VMD (D-053, which revises D-050).
- Observation of the reference peer (`server_example_sg`, a black box, with the MMS client of `igs-iso9506-mms`): its named variables list
  `LLN0$SP$SGCB` and five of its attributes, without `ResvTms`. Our server lists the six.
- Tests: `tests/setting_groups.rs::the_sgcb_and_its_attributes_are_named_in_the_domain_with_their_structure` (over MMS: the names, and the six
  components of the structure in order). Bench: `bench/tests/test_x4_setting_groups.py` (the peer and our server list the SGCB; the capture of
  the peer decodes cleanly in tshark). Matrix X4 in `docs/interop.md`. Registry row SGCB-001 in `docs/capabilities.tsv`.

## Not done

- The Owner of the BRCB. 8-1 says a V-Get of Owner returns the IP address of the application entity that reserved the block (4 octets IPv4, 16
  IPv6), or NULL for a preconfigured owner without a ClientLN and for a dynamic client. Serving it needs the network address of the association.
  The `Peer` struct of `igs-iso9506-mms` carries the association identifier and the AARQ identity only. Adding the address is a public API change
  in the sibling crate: a decision for the maintainer, not taken here.
- The reverse direction of the SGCB bench (the reference client reads the SGCB of our server): there is no SGCB example client in the peer image
  that this bench uses.
