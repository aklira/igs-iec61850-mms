# Q1 — Double-point and tap-command basic types (task of igs-iec61850-mms)

## Prompt

Run task Q1 of `IMPLEMENTATION.md` (depends on A2, S3), started with `Dbpos`. Done when a logical node holding a double point is served, the
vectors of its values pass, and the capability row is updated. The product uses in section 0 of `docs/capabilities.md` depend on it: a breaker
cannot be served while `XCBR.Pos` is refused (product uses: the header of `IMPLEMENTATION.md`).

## Summary

- **Source**: 7-2 Table 24 (DpStatusKind, the form of `Dbpos`): `intermediate-state` 0, `off` 1, `on` 2, `bad-state` 3. The prepared text is in
  `~/Dev/norm_preparation/docs/spec/7-2`. The catalogue does not hold DpStatusKind (the NSD only names it), so the literals are in the code
  (`acsi::DoublePosition`), with their source in the comment and in D-042.
- **Size**: the largest value is 3, so two bits (`coded_enum_size(3)`, 8-1 §8.1.2.3). The type description is a bit string of two bits.
- **Core** (`acsi.rs`, `model/types.rs`): `DoublePosition`, `double_position_to_data` and `double_position_from_data`; `Dbpos` is resolved in
  `types::basic`.
- **Tests**: `acsi.rs` (vectors for the four values, MSB first; reading past the size; wrong type), `tests/model.rs` (`XCBR1$ST$Pos$stVal` has a
  two-bit type and a zero initial value). The refusal test moved from `Dbpos` to `BrcbTrk` (`LTRK`), which still holds `TrgOps` and `EntryID`.
- **Result**: `cargo test --workspace --all-features` passes with 309 tests (306 before, plus three new); fmt, clippy (the known `xtask` manifest
  warning, unchanged) and rustdoc pass.

## Tcmd (second step of Q1)

- `Tcmd` is StepControlKind (7-2 Table 23): `stop` 0, `lower` 1, `higher` 2, `reserved` 3, a two-bit coded enumeration (`StepCommand` in
  `acsi.rs`, resolved in `types::basic`). Vectors and extra-bit reading are in `acsi.rs`; `model/types.rs` has a unit test for both types.
- Finding: in the namespace `Tcmd` is only the `ctlVal` service parameter of BSC and BAC, not a data attribute. Nothing served is refused for it;
  it matters with the control task (K), so the mapping is ready there.
- Result: 311 tests pass; fmt, clippy (the known `xtask` manifest warning), rustdoc and `statements --check` pass.

## Open

- The write of a `Dbpos` or a `Tcmd` (control) stays refused until task K.
- `PhyComAddr` stays refused by decision (D-043): its form depends on the GOOSE and sampled value profile, which is out of scope.

## Other basic types (second part of Q1)

- `TrgOps`, `OptFlds`, `SvOptFlds`: bit strings of their minimum size (six, ten and seven bits), with the bit positions of 8-1 Tables 37,
  41 and 42 (`acsi.rs`, `trigger_options_*`, `report_options_*`, `sv_options_*`).
- `EntryID`: an octet string of exactly eight octets; `EntryTime`: the six-octet TimeOfDay with its day (`entry_id_*`, `entry_time_*`).
- `model/layout.rs`: the initial value of an octet string is zero octets of its size, and that of a `BinaryTime` the zero time of day.
- Served now: `BrcbTrk`, `UrcbTrk`, `LocbTrk`, `SgcbTrk` (tracking of the reports, logs and setting groups). Still refused: the GOOSE and sampled
  value tracking (`GocbTrk`, `UsvcbTrk`, ...), which hold a `PhyComAddr`.
- Found while testing: `GocbTrk.dstAddress` is refused as `Unsupported`, not `UnmappedType`, because its type comes from the specific mapping.
- Result: 318 tests pass; fmt, clippy (the known `xtask` warning), rustdoc and `statements --check` pass.
