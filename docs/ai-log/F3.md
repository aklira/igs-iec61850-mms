# F3 — Catalogue generation

## Prompt

Run task F3 of `IMPLEMENTATION.md`.

## Summary

`cargo xtask catalogue [--check]` (new module `xtask/src/catalogue.rs`, dependency `roxmltree`) writes
`crates/igs-iec61850-mms-core/src/catalogue/generated/` from the NSD files of 7-2, 7-3, 7-4 (2007B6) and
the SNSD and AppNS of 8-1 (2003A4). The types and lookups are hand-written in `catalogue/mod.rs`
(`cdc`, `ln_class`, `enumeration`, `constructed_attribute`, `functional_constraint`,
`LnClass::all_data_objects` for inherited data objects, bounded in depth). Decision D-002.

Counts written and checked against the XML: 27 basic types, 12 + 1 functional constraints, 39 + 3
presence conditions, 86 enumerations (678 literals), 14 constructed attributes, 70 CDCs (903 data
attributes), 204 logical-node classes (39 abstract, 1431 data objects), 8 service CDCs.

Found on the way: the plan named the 2007B3 releases fetched by P5, but the IEC publishes later
releases (2007B4 to B6, 2003A3, A4) under names with a capital `Light`. P5 was corrected in
`norm_preparation` and the generation reads the latest releases; they already carry the ten TISSUE
decided "catalogue" by P7, so nothing is patched on top.

Generated modules hold one entry per line and are declared `#[rustfmt::skip]`. Each carries the IEC
copyright notice of its code component, the attribution note and the SPDX identifier
`IEC-Code-Components-EULA`; `NOTICE` gives the licence conditions and disclaimer.

Tests: `crates/igs-iec61850-mms-core/tests/catalogue.rs` (namespace identities, counts, SPS attributes
in order with their trigger options, the behaviour enumeration, LPHD.Proxy, XCBR.Pos inherited from
its base, every CDC, base class and FC reference resolved).
