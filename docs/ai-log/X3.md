# X3 — File services in the model (task of igs-iec61850-mms)

## Prompt

Run task X3 of `IMPLEMENTATION.md` (production phase X): the file services of the server, the SetFile decision, and bench rows for GetFile,
GetFileAttributeValues and DeleteFile against the reference peer. The IEC file class of the SCL model (Q6) is a question for the maintainer.

## Decisions taken by the maintainer

- The IEC file class of the SCL model is dropped from X3: no source for it in the prepared texts of 61850-6 and 7-x.
- SetFile (ObtainFile) is refused, not served.

## Summary

- The server serves its file store: `ServedModel::add_file`; `igs61850-server --files-dir DIR` loads the regular files of a directory (no
  subdirectories, no links, 16 MiB per file at most). The profile declares the file feature for the server (`files: true`).
- Tests: `tests/files.rs` (five, over MMS): the listing, GetFile, FILE-NON-EXISTENT for a missing file, the deletion, and the declared services.
- Manual check: `igs61850-server --files-dir` with the MMS client of `igs-iso9506-mms` (`files`, `get`, `delete`, commands added there and
  not committed). The listing, the content and the deletion behave as the tests say.
- Decision recorded: D-054 in `PROVENANCE.md`.

## Reference peer: no bench row yet

- The reference file example (`server_example_files`) refuses every path tried: `.`, `/tmp`, `data`, `config`, `files`, `tmp`, `test.txt` placed
  in its working directory with a volume (`file-non-existent`, error class 7). The peer's own tool `file-tool dir` fails with "Error retrieving
  file directory", and `file-tool info` and `get` give no answer. A request for `/` gives no answer within 20 seconds.
- Its directory convention is not known, and its documentation is not in the peer image. The bench rows for GetFile, GetFileAttributeValues and
  DeleteFile wait for that convention, or for a different example that serves a known file set.
