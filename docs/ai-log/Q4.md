# Q4 — Buffered reports: general interrogation and reservation (task of igs-iec61850-mms)

## Prompt

Run task Q4 of `IMPLEMENTATION.md` (depends on B2): the general interrogation (`GI`) and the reservation (`ResvTms`) of the buffered
block. Done when a reconnecting client receives the full state without reading every member, and the reservation rules are tested
with controlled time and between two associations. The decisions are in D-044.

## Summary

- **Core** (`report/brcb.rs`): `Write::GeneralInterrogation` and `Write::ReserveTime(u16)`; `Refusal::Reserved` and
  `Refusal::GeneralInterrogationNotAllowed`; the holder and its time (`reserved_by`, `reserve_time`), the owner (`owner`, set by the
  enabling), `Timer::Reservation` (shared with the unbuffered block, which never arms it).
  - GI: refused while disabled; while enabled with the trigger on, the open window is closed, then one report of all members with the
    reason general-interrogation, `EntryID` NULL, not kept in the history.
  - Reservation: free → reserved for the writer; holder → time changed; zero → released (positive on a free block); other client → refused
    for every write. Loss of the holder → kept for its time (timer), then free.
  - Loss of an association: only the owner disables the block (before, any loss did).
- **Server** (`igs-iec61850-mms/src/buffered.rs`): `ResvTms` in the attribute list (before `Owner`), read as the reservation time; writes
  `GI` TRUE and `ResvTms`; a negative `ResvTms` is `object-value-invalid`; `Reserved` is `temporarily-unavailable`; the loss of a
  reservation holder reaches the core (`released`).
- **Client** (`client_buffered.rs`): `BufferedWrite::Reserve(seconds)` and `BufferedWrite::GeneralInterrogation`.
- **Tests**: `tests/report_buffered_reservation.rs` (10, controlled time); `tests/buffered.rs` (two association tests). Workspace: 330 tests
  pass; fmt, clippy (the known `xtask` manifest warning), rustdoc and `statements --check` pass.
- **Documentation**: D-044, `docs/capabilities.tsv` (row BRCB-004, BRCB-002 corrected), `docs/statements.md` (regenerated), README and
  `docs/conformance-drafts.md` (the "no GI, no reservation" statement removed).

## Findings while testing

- The server's `released` forwarded the loss only for the owner. A holder that was not the owner would never have had its reservation
  released. Fixed by forwarding the loss also to the holder; the core ignores the loss for a block it does not own (the owner rule).
- The first version of the core disabled the block on any loss. That was corrected with the owner rule, and the existing tests still pass.
- A first wording claimed the GI report was not segmented. It goes through the server's segmentation like every report; the docs were
  corrected.
