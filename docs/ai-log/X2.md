# X2 — Journal services over MMS (task of igs-iec61850-mms)

## Prompt

Run task X2 of `IMPLEMENTATION.md` (production phase X): the log control blocks served over MMS, the journal fed from the core `Log`,
ReadJournal on the server (QueryLogByTime and QueryLogAfter), the gateway replay after a lost association, and the class `journal` of
GetNameList (G14). Done when: the server answers the queries, a client recovers the events after a lost association, and the bench rows
pass against the reference peer.

## Summary

- SCL: `LogControl` and `Log` are declared (`Configuration.logs`, `Configuration.journals`); a `logName` that names no `Log` of its node is
  refused (SCL-003).
- Journals: each `Log` is an MMS journal of its node (512 entries). A block with `logEna` records the changes of its data set: the transition of
  LogEna is the first entry (EVENT-DATA), a change is an entry with the reference, the value and the reason code (8-1 Table 77).
- ReadJournal reads the journal from the start, by time (both ends), and from an entry (QueryLogAfter). Tests: `tests/logs.rs`,
  `tests/log_control.rs`.
- The log control block over MMS: GetLCBValues (its structure, Table 75) and SetLCBValues (LogEna; LogRef, DatSet, TrgOps, IntgPd while
  disabled). Test: `tests/log_control.rs`.
- Recovery after a lost association: a client reads the entries after its last identifier (test `a_client_that_lost_its_association_...`).
- The gateway replays a downstream journal after a reconnection (`gateway::replay_journal`, test `tests/gateway_replay.rs`). D-057.
- G14: GetNameList lists the journal class of a domain (`igs-iso9506-mms`, committed separately).
- Finding, fixed: the devices of an SCL file were named by their instance (`LD1`); the rule of IEC 61850-6 §8.5 gives `IED1LD1` (D-058). The
  reverse bench row of the log example found our model only after this fix.
- The reverse bench row (`bench/tests/test_x2_logs_reverse.py`): the example finds the log, enables it and reads its LCB; the protocol passes.

## Not done

- The example receives no entry: no change is recorded after its request. The reading of ReadJournal against the reference client, with
  entries, is not shown yet (docs/interop.md, matrix X2). This is why the done-when of X2 stays partial.
- The pages of ReadJournal: one page per answer; a journal of more pages is read by the caller from its last entry.
- The trigger qualities qchg and dupd are not separated (D-045); bufTm is not mapped (8-1).
- The peer side of the logs is not in the bench: the reference image has no server example with logs.

## Decisions

D-056 (the journals and the recording), D-057 (the LCB over MMS and the replay), D-058 (the device names).
