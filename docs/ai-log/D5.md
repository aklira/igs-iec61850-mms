# D5 — Client reporting (task of igs-iec61850-mms)

## Prompt

Run task D5 of `IMPLEMENTATION.md` (dependencies D4 and A6): a client API to configure and enable the unbuffered blocks, and to receive decoded
reports. Done when AT-09 passes between our client and server.

## Summary

- Core: the bit strings of the options, the triggers and the reasons decode what they encode (`report/encode.rs`).
- Server (`reports.rs`, `model.rs`): the attributes of each unbuffered block are served as variables `node$RP$block$attribute`; reads answer from the
  block's state; writes are requests of the state machine, with their refusals as access results. D-028.
- Client (`client_report.rs`): `urcb_values`, `urcb_write` (`UrcbWrite`), `decode_report` (table 74, self-describing through the options).
- The control and the report paths share the request routing of the served model (the items of a read or a write are sorted: control, block
  attribute, VMD).
